# Codex transcript formats

The transcript supports both typed app-server items and protocol envelopes stored
inside message text. Persisted and live items use the same server normalizer in
`server/src/codex_transcript.rs`; text envelopes are presented by
`web/src/lib/codex-message-format.ts` and `CodexMessageContent`.

The October 2, 2026 audit examined local active and archived session records and
the experimental JSON schema generated by codex-cli 0.159.3. Protocol behavior was
also checked against the [official App Server documentation](https://learn.chatgpt.com/docs/app-server).
No session contents are copied into this repository; tests use synthetic data.

| Text envelope | Presentation |
| --- | --- |
| `send_user_message_question_reply` | Each question and its answer; internal question references stay out of the display |
| `proposed_plan` | Plan card with Markdown |
| `turn_aborted` | Interruption notice |
| `environment_context` | Expandable environment details |
| `recommended_plugins` | Expandable plugin context |
| `INSTRUCTIONS` | Expandable project instructions |
| `codex_internal_context` | Expandable Codex context; attributes and nested content are accepted |
| `external_codex_apps_open_page` | Expandable page context with formatted JSON |
| `in-app-browser-context` | Expandable browser context |
| `skill` | Expandable skill instructions |

Envelopes must start on their own line outside fenced or indented code. Ordinary
HTML, inline examples, blockquotes, and incomplete envelopes retain their original
text. Malformed reply payloads and future `codex_`, `external_codex_`, and
`send_user_message_` envelopes remain inspectable in details.

Standalone `::code-comment{...}` review directives render as finding cards with
Markdown bodies, priorities, and file/line links. Quoted attributes accept escaped
quotes and braces. Malformed and future directives retain their attributes in
expandable details. Image transport markers are omitted only when the input also
contains an actual image attachment.

`visualize` reference markers expose their saved HTML artifact as a file card.
Downloads use the existing workspace file route and its path restrictions; this
does not execute arbitrary HTML or extend file access beyond the chat workspace.

The current schema has 19 typed items: `userMessage`, `hookPrompt`, `agentMessage`,
`functionCallOutput`, `plan`, `reasoning`, `commandExecution`, `fileChange`,
`mcpToolCall`, `dynamicToolCall`, `collabAgentToolCall`, `subAgentActivity`,
`webSearch`, `imageView`, `sleep`, `imageGeneration`, `enteredReviewMode`,
`exitedReviewMode`, and `contextCompaction`. Tools expose results, errors, and
diffs in expandable details. Reasoning exposes summaries only. Generated images
link to their saved artifact; image bytes are not printed as text. Unknown items
and input types retain their data through a fallback view.

Blocking `item/tool/requestUserInput` requests use a question form and send
`answers[questionId].answers` in the JSON-RPC response. Resolved requests and
requests from finished turns are cleared. Agent-message `questions` use the same
form and produce `send_user_message_question_reply` envelopes with references
`["request_user_input_async", itemId, questionIndex]`. Replies steer the active
turn with `expectedTurnId`, or start a turn when the chat is idle. No option is
submitted until the user explicitly answers. Answered questions are recognized
from transcript references after reload.

Regression tests cover format parsing, readable rendering, explicit submission,
retry after errors, every typed item, retained tool results, question validation,
steered user-message identity, and code-fence escaping.
